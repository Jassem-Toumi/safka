# Backend decisions

Interpretations of ambiguous points in `Creator_Sponsorship_Backend_Spec-final.md`. Add new ones at the bottom with the date.

| # | Spec ref | Decision | Why |
|---|---|---|---|
| D1 | whole | Final spec supersedes the original backend spec wherever they conflict. The original is background only. | Master dev's final call (2026-11-22). |
| D2 | §2 | Node 24.22.3 (latest 24.x LTS), pinned via `.nvmrc` and `engines`. npm, not pnpm. | Spec asks for ≥24.16 within 24.x and npm commands. |
| D3 | §2 | Host check is strict: only `APP_ORIGIN`'s host (`127.0.0.1:3000`). `localhost:3000` is rejected with 403. Writes need `Origin` equal to `APP_ORIGIN` (or no Origin and `Sec-Fetch-Site` same-origin/none, e.g. curl/tests). | "Validate hosts and browser write origins against the configured loopback origin." Frontend must use `http://127.0.0.1:3000`. |
| D4 | §2 | Session cookie `safka_session` holds a 256-bit random token; DB stores only its sha256. 7-day expiry. | Opaque server-generated session, nothing guessable stored. |
| D5 | §2 | `GET /demo/accounts` returns the standard list shape `{ items, nextCursor: null }`. | §7 says retain list shape. |
| D6 | §2/§7 | `Me.profileReady`: creators → profile has been published at least once; brand/admin → true. | Original spec uses it to route onboarding vs inbox. |
| D7 | §3 | No opted-in real YouTuber yet. All seeded creators are fictitious, named "(sample)", `dataMode: SAMPLE`, evidence `kind: SAMPLE` with `example.com` URLs. A blank "Live Demo Creator" draft account exists for a live You.com run once someone opts in. | User instruction; spec forbids passing fixtures off as live. |
| D8 | §3 | Channel normalization accepts `@handle`, `youtube.com/@handle[/tab]`, `youtube.com/channel/UC…[/tab]` on youtube.com / www / m hosts, http upgraded to https. Rejects `/c/`, `/user/`, watch URLs, look-alike hosts, credentials, ports. Uniqueness key is lowercase handle (`yt:@handle`) or channel ID (`yt:UC…`), enforced only among LISTED profiles (`listed_channel_key`). | Spec: "deduplicate listed channel identities where the canonical keys match". |
| D9 | §3/§7 | Profile input sends topics as free text strings + `selectedEvidenceIds`; the server normalizes slugs and derives each label's `origin` from the selected evidence rows that support it (`evidence.topics_json/formats_json`). | Keeps frontend simple; provenance can't be forged by the client. |
| D10 | §5 | One-open-negotiation is enforced by a partial unique index on `deals(negotiation_context) WHERE status='NEGOTIATING'`. Before inserting, the transaction materializes any expired NEGOTIATING row in that context to `EXPIRED`. | Belt-and-braces with the in-transaction check; spec excludes expired rows. |
| D11 | §5 | Contract additions beyond the spec list (additive only): `Deal.sample`, `DraftBatch.late/changeRequest`, `Publication.submittedAt/late/sample`, `MetricResult.shortfallPct`, `Campaign.hasOpenNegotiations/createdAt`, `CampaignReport.sample`, `EnrichmentResult.profileVersion`, `CreatorProfile` shape, `ApiErrorBody.error.details` (e.g. `{ dealId }` for `ACTIVE_NEGOTIATION_EXISTS`). | Frontend needs them; spec lists minimums. |
| D12 | §6 | Seed MP4s are team-provided files in `seed-assets/seed-draft-option-{1,2}.mp4`; seed copies them to `.local/uploads/`. Until provided, seeded draft rows exist but their media endpoint will 404. | User will supply videos. |
| D13 | §6 | The sample report lives on a dedicated sample campaign ("Felt desk mat launch (sample)") with one COMPLETED/RELEASED sample deal: clicks 420/600 (BELOW_TARGET, 30%), views 21,500/20,000 (MET). Metrics are stored only in `deals.sample_metrics_json` on `is_sample=1` deals. | Keeps sample numbers isolated from real totals. |
| D14 | §6 | The held-dispute demo deal is on a non-sample campaign ("Whisper 75 pre-launch (moderation demo)", $1,000 budget, $400 HELD) so refund visibly frees exactly $400. | Acceptance test 5. |
| D15 | §3.1 | Listing a channel already LISTED by another profile → **400** `VALIDATION_ERROR` with `fields.channel` ("already listed"). Error codes map to fixed HTTP statuses, so this is 400 rather than 409. Missing listing requirements → 400 with `fields` per blocker and `details.listingBlockers`. | Keeps one status per error code. (2026-11-22, Session 2) |
| D16 | §3.5 | Visibility changes don't bump `version` (only draft edits do). LISTED snapshots the current draft and sets `published_version = version`. HIDDEN keeps `published_json` so existing deals still render. Card `dataMode` is `SAMPLE` for sample profiles, `LIVE` if any selected evidence is `PUBLIC`, otherwise `SELF_REPORTED`. | `hasUnpublishedChanges = version !== published_version` stays meaningful. |
| D17 | §3.2–4 | Enrichment needs a saved, valid channel (400 `fields.channel` otherwise). It doesn't change `version`. Evidence is upserted by (creator, channel, URL), so re-runs keep IDs and the creator's selection stable. If version or channel changed during the call, the run is recorded with `applied=0`, nothing is saved, and the response is 409 `STALE_PROFILE`. A `FAILED` search is HTTP 200 with `status: FAILED` and `errorCode` ∈ `TIMEOUT`, `QUOTA_EXCEEDED`, `AUTH_FAILED`, `PROVIDER_ERROR`, `BAD_RESPONSE`. | Terminal result per spec; no silent overwrite or fixture fallback. |
| D18 | §3.2 | Smoke test on 2026-11-22 (generic query, `npm run youcom:smoke`): the keyless endpoint connects and lists `you-search`, but calls return "Free tier limit exceeded" → `QUOTA_EXCEEDED`. A live demo needs `YDC_API_KEY`. The result parser accepts `structuredContent`, JSON text (`results.web[]` etc.) or plain-text listings, because the success payload hasn't been observed yet. | Can't verify the success shape without quota. |
| D19 | §3.3 | Identity match: case-insensitive `@handle` not followed by another handle character (a trailing sentence "." is allowed), or the exact `UC…` channel ID, anywhere in URL/title/snippet. Keyword map lives in `src/server/youcom/extract.ts`. In evidence a bare "keyboard" isn't enough (could be a piano); briefs also accept bare "keyboard". | Spec: similar display names never establish identity. |
| D20 | §7 | `GET /creators/{id}` is brand-only like the list (creators see their own card via `/creator/profile`). `q` is a case-insensitive substring over display name and bio. `GET /products/{id}` was added (owned only). Landing URLs: https only, no credentials, no localhost/`.local`/single-label hosts, no private/loopback/link-local/CGNAT IPv4 or loopback/ULA/link-local IPv6 literals. | Frontend convenience; SSRF-style hygiene. |
| D21 | §4 | RULES parse: dollar amounts come **only from the prompt** (product copy may contain prices). An amount followed by "per post/video/creator", "/video" or "each", or preceded by "up to/max/at most", is `preferredMaxPerPostCents`. The first other amount is `budgetCents`. `k` suffix and commas are supported. "N views" / "N clicks" set the targets. Topics come from prompt + product text; formats from the prompt only. Objective is the one whose keyword appears first in the prompt. Title is the product name; goal is the prompt. | "Explicitly written" amounts; deterministic. |
| D22 | §4 | Campaign rules: `confirm: true` activates (needs a valid `Brief` with ≥1 topic and a budget). Edits to an ACTIVE campaign must keep it activatable. CLOSED campaigns are read-only (409 `INVALID_STATE`). Closing with an unexpired NEGOTIATING deal → 409 `INVALID_STATE`. The budget floor (`BUDGET_EXCEEDED`) applies when committed + spent > 0. Budget totals include sample deals on the sample campaign (they're isolated to that campaign). | Spec §4/§5 plus a minimal state machine. |
| D23 | §4 | Matches need an ACTIVE campaign (409 `INVALID_STATE` otherwise) and return the list shape `{ items, nextCursor: null }`. Rate cap = min(max(0, remaining), preferred max if set). `formatMatch` is true when the brief has no formats; ranking uses the overlap count. Unknown views sort below known ones. Reasons: one per matched topic (quoting the first approved evidence title, `evidenceIds` only from the card's approved evidence), one per overlapping format, rate, and typical views labeled sample/self-reported. The angle uses the first overlapping format, else the creator's first format. Sound-test creators get the spec's example angle for COMPARISON/DEMO. | Spec §4 ranking order. |
| D24 | §3, §9.1 | The user approved using real public YouTube channels for the demo (2026-11-22): @hipyotech, @Glarses, @alexotos, @TaeKeyboards, each verified by live search. They're seeded as DRAFT "(demo channel)" accounts with only the channel set. The bio says they aren't Safka members. `npm run demo:enrich` runs one live search each and lists them using only PUBLIC-backed tags and sources. Rates and views stay null, with nothing invented. Channels without both a public topic and a public format stay in draft. | Honest provenance for real people. |
| D25 | §6 | Seed MP4s are generated locally by `scripts/make-seed-mp4.swift` (AVFoundation, H.264 baseline, 640×360, 6 s, moov atom first, about 60 KB each) and committed to `seed-assets/`. `npm run demo:videos` regenerates them. Seed fixes the placeholder `uploads.size_bytes` once the files exist. | User asked for static MP4s; there's no ffmpeg on the machine. |
| D26 | §3.3 | Format keywords: "typing test" and "ASMR" also suggest `DEMO`. | Typing-sound videos are demos, consistent with "sound test". |
| D27 | §7 | `Deal.creator.id` is the creator **profile** ID (the same ID as directory cards and `CreateDealInput.creatorId`). `Deal.brand.id` is the brand user ID. | One creator ID across the API. (2026-11-22, Session 3) |
| D28 | §2, §5 | Admins can read a deal (and stream its drafts) only if it has ever had a dispute. Resolution actions need an open dispute whose ID matches `disputeId` (otherwise 404). Other users' deals → 404. | "Admin access limited to dispute review." |
| D29 | §5 | A participant trying an action that isn't theirs → 403 `FORBIDDEN`. Wrong state → 409 `INVALID_STATE`. A `proposalId` that isn't the latest → 409 `STALE_DEAL`. ACCEPT re-checks the dates; if the draft date has passed → 400 with `fields.draftDueAt` (counter with new dates). | Distinguishes "not yours" from "not now". |
| D30 | §5 | EXPIRED is derived from the server clock on every read. It's written to the row only when a new offer is created in the same negotiation context (so the partial unique index frees up). Actions on an expired proposal → 409 `PROPOSAL_EXPIRED`, checked after the version check. | No scheduler. |
| D31 | §5 | Idempotency scope: `(actor, "CREATE_DEAL" or "DEAL_ACTION:<dealId>", key)`. The fingerprint covers the parsed body. The replay check runs first inside the tx, before access, version and state checks. Replays return the saved status and body plus the header `Idempotent-Replay: true`. A missing key → 400. | Spec §5 order. |
| D32 | §6 | Uploads: creator only, in AGREED / REVISION_REQUESTED. At most 6 READY (unattached) uploads per deal. A Content-Length precheck rejects oversize requests with 413 before parsing. The file is written before the tx and deleted if the tx fails. `UPLOADS_DIR` overrides the folder (tests). A multi-range request gets a full 200; HEAD is supported. Labels are "Option 1/2". | Spec §6. |
| D33 | §6 | Deal report window = `publishedAt` to +7 days. Live metrics are always `actual: null`: `NO_TARGET` with no target, `PENDING` before the window ends (or before publication), `INSUFFICIENT_DATA` after it. The campaign report lists only deals that reached agreement. `agreedCount` = ever accepted, `publishedCount` = ever published, `completedCount` = COMPLETED, and `countsByStatus` uses effective status. | "Counts include deal history." |
| D34 | §7 | Inbox: REPORT_ISSUE and WITHDRAW are secondary, so they alone don't count as `needs_action` (a brand waiting on the creator shows under `in_progress`). With no filter, every visible deal is returned. Admins see deals that have disputes. Ordering: needs action first, then `updatedAt` descending. | Spec: "REPORT_ISSUE is a secondary action". |
